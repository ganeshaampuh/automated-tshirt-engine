# CSV Batch Implementation Plan (Plan 3 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upload a CSV of family birthday sets, have them generated in the background with human review, and download one ZIP of print-ready PNGs for the sets you approve.

**Architecture:** Three hardening tasks first, because batch mode is what makes their absence dangerous: a single guarded path for fetching user-supplied image URLs, a CI workflow so the golden-image suite is actually enforced, and a per-member state shape in the database that the current `preview_urls` column cannot express. Then the batch itself: a parser that rejects a bad CSV before anything is created, a self-chaining processing route that renders sets a few at a time and survives interruption, a gallery that shows one card per set with every member's preview, and a streaming ZIP that never holds more than one set in memory.

**Tech Stack:** Existing — Next.js 16 App Router, TypeScript, Vitest, Playwright, Zod, Drizzle + Neon, `@vercel/blob`, `fflate` (streaming `Zip`), `sharp`, `@napi-rs/canvas`. New: `@vercel/functions` for `waitUntil`.

**Spec:** `docs/superpowers/specs/2026-09-08-tshirt-design-generator-design.md` (§5, §8.2, §9, §11, §12)

## Global Constraints

- **Every fetch of a user-supplied URL goes through `fetchRemoteImage`** (Task 1). No other code may call `fetch` or `readFile` on a string that came from a CSV, a form, or the database.
- Print rules are unchanged: 300 DPI, square canvas of `maxPx(sizeClass)` (adult 3425 / kids-0-1 2126 / kids-1-9 2362), 3% safe inset, export cropped to the layers' bounding box plus 1%.
- A set never fails because the LLM misbehaved: `chooseStyle` already retries once then falls back with `aiFallback: true`. A set may fail for a bad image, and that failure is recorded per set, never aborting the batch.
- Batch limits: **200 sets, 1000 members**, processing concurrency **3**.
- One set's render peaks around 380 MB and takes about 1.3 s locally. Never hold more than one set's buffers at a time; the batch ZIP is streamed.
- Server Actions return `ActionResult<T>` from `src/lib/actionResult.ts`. Expected failures carry Indonesian wording as data; only unexpected faults throw.
- UI copy is Indonesian. Secrets are never logged, returned, or written to a row.
- Commit after every task with a conventional-commit message.

```ts
import { lookup as dnsLookup } from "node:dns/promises";
import { isIP } from "node:net";

export class RemoteImageError extends Error {
  constructor(message: string) { super(message); this.name = "RemoteImageError"; }
}

export const MAX_REMOTE_BYTES = 16 * 1024 * 1024;
export const REMOTE_TIMEOUT_MS = 15_000;
export const MAX_REDIRECTS = 3;

export type DnsLookup = (hostname: string) => Promise<string[]>;

const defaultLookup: DnsLookup = async host =>
  (await dnsLookup(host, { all: true, verbatim: true })).map(a => a.address);

const v4 = (ip: string) => ip.split(".").map(Number);
const inNet = (ip: string, net: string, bits: number) => {
  const toInt = (s: string) => v4(s).reduce((n, o) => (n << 8) + o, 0) >>> 0;
  const mask = bits === 0 ? 0 : (~0 << (32 - bits)) >>> 0;
  return (toInt(ip) & mask) === (toInt(net) & mask);
};

export function isBlockedAddress(raw: string): boolean {
  let ip = raw.trim().toLowerCase();
  // An IPv4-mapped IPv6 address is just IPv4 wearing a hat; unwrap before deciding.
  const mapped = /^::ffff:(\d+\.\d+\.\d+\.\d+)$/.exec(ip);
  if (mapped) ip = mapped[1];

  if (isIP(ip) === 4) {
    return (
      inNet(ip, "127.0.0.0", 8) || inNet(ip, "10.0.0.0", 8) || inNet(ip, "172.16.0.0", 12) ||
      inNet(ip, "192.168.0.0", 16) || inNet(ip, "169.254.0.0", 16) || inNet(ip, "100.64.0.0", 10) ||
      inNet(ip, "0.0.0.0", 8) || inNet(ip, "224.0.0.0", 4) || ip === "255.255.255.255"
    );
  }
  if (isIP(ip) === 6) {
    return ip === "::1" || ip === "::" || /^f[cd]/.test(ip) || /^fe[89ab]/.test(ip) || /^ff/.test(ip);
  }
  return true; // not an address we can reason about
}

export function assertPublicHost(hostname: string, addresses: string[]): void {
  if (addresses.length === 0) throw new RemoteImageError(`Alamat ${hostname} tidak bisa ditemukan.`);
  // Every answer must be public: one private record is enough to make the host unsafe.
  if (addresses.some(isBlockedAddress)) throw new RemoteImageError(`Alamat ${hostname} tidak diizinkan.`);
}

export async function fetchRemoteImage(url: string, opts: { fetchFn?: typeof fetch; lookup?: DnsLookup } = {}): Promise<Buffer> {
  const doFetch = opts.fetchFn ?? fetch;
  const lookup = opts.lookup ?? defaultLookup;
  let current = url;

  for (let hop = 0; hop <= MAX_REDIRECTS; hop++) {
    let parsed: URL;
    try { parsed = new URL(current); } catch { throw new RemoteImageError("Alamat gambar tidak valid."); }
    if (parsed.protocol !== "https:") throw new RemoteImageError("Alamat gambar harus memakai https.");
    // Resolve and check on EVERY hop: a redirect is a fresh, unvetted destination.
    assertPublicHost(parsed.hostname, await lookup(parsed.hostname));

    const ctrl = new AbortController();
    const timer = setTimeout(() => ctrl.abort(), REMOTE_TIMEOUT_MS);
    let res: Response;
    try {
      res = await doFetch(current, { redirect: "manual", signal: ctrl.signal, headers: { accept: "image/*" } });
    } catch {
      throw new RemoteImageError("Gagal mengambil gambar dari alamat itu.");
    } finally {
      clearTimeout(timer);
    }

    if (res.status >= 300 && res.status < 400) {
      const location = res.headers.get("location");
      if (!location) throw new RemoteImageError("Gagal mengambil gambar dari alamat itu.");
      current = new URL(location, current).toString();
      continue;
    }
    if (!res.ok) throw new RemoteImageError(`Gambar tidak bisa diambil (${res.status}).`);

    const type = res.headers.get("content-type") ?? "";
    if (!type.startsWith("image/")) throw new RemoteImageError("Alamat itu bukan gambar.");
    const declared = Number(res.headers.get("content-length") ?? NaN);
    if (Number.isFinite(declared) && declared > MAX_REMOTE_BYTES) throw new RemoteImageError("Gambar terlalu besar.");

    return await readCapped(res);
  }
  throw new RemoteImageError("Terlalu banyak pengalihan alamat.");
}

/** Reads the body a chunk at a time so a lying `content-length` cannot blow past the cap. */
async function readCapped(res: Response): Promise<Buffer> {
  if (!res.body) throw new RemoteImageError("Gambar kosong.");
  const chunks: Uint8Array[] = [];
  let total = 0;
  const reader = res.body.getReader();
  for (;;) {
    const { done, value } = await reader.read();
    if (done) break;
    total += value.byteLength;
    if (total > MAX_REMOTE_BYTES) { await reader.cancel(); throw new RemoteImageError("Gambar terlalu besar."); }
    chunks.push(value);
  }
  return Buffer.concat(chunks.map(c => Buffer.from(c)));
}
```

```ts
export type MemberStatus = "queued" | "ready" | "failed";
export type MemberState = { status: MemberStatus; previewUrl?: string; widthCm?: number; heightCm?: number; error?: string };
export type MemberStates = Record<string, MemberState>;

export const initialStates = (ids: string[]): MemberStates =>
  Object.fromEntries(ids.map(id => [id, { status: "queued" as const }]));

export function setMemberState(states: MemberStates, id: string, patch: Partial<MemberState>): MemberStates {
  if (!(id in states)) return states;
  return { ...states, [id]: { ...states[id], ...patch } };
}

export function rollUp(states: MemberStates) {
  const all = Object.values(states);
  return {
    total: all.length,
    ready: all.filter(s => s.status === "ready").length,
    failed: all.filter(s => s.status === "failed").length,
    queued: all.filter(s => s.status === "queued").length,
  };
}

export const allReady = (states: MemberStates) =>
  Object.values(states).length > 0 && Object.values(states).every(s => s.status === "ready");
```

**Interfaces:**
- Produces:
  ```ts
  export type ParsedRow = { line: number; input: SetInput };
  export type RowError = { line: number; message: string };            // Indonesian
  export type ParseResult = { rows: ParsedRow[]; errors: RowError[] };
  export const MAX_SETS = 200;
  export const MAX_MEMBERS = 1000;
  export function parseCsv(text: string): string[][];                   // RFC4180: quotes, escaped "", CRLF
  export function parseBatchRows(text: string): ParseResult;
  ```

- CSV columns (spec §8.2): `kid_name, age, theme, members` required; `language, shirt_color, clipart_url, sku_prefix, note` optional. Header row required; column order free; unknown columns ignored.
- `members` syntax: `Label:sizeClass` separated by `;`, where the token `kid` in place of a size class marks the birthday child and picks the class by age (`age <= 9` → `kids-1-9`, else `adult`; `age <= 1` → `kids-0-1`). Exactly one `kid` per row.
- `shirt_color` accepts a hex or one of the named colours the editor offers (`putih, hitam, navy, merah, pink, kuning`), default `#ffffff`. `language` defaults to `id`.
- Validation is total: a row that fails produces a `RowError` and no `ParsedRow`; **nothing is created until the caller decides**, so a bad file never leaves half a batch behind.

### Task 6: Batch processing

**Files:**
- Create: `src/app/api/batch/[id]/tick/route.ts`, `src/lib/processSet.ts`
- Test: `tests/lib/processSet.test.ts`

**Why a self-chaining route:** a Hobby Vercel plan runs cron once a day, so cron cannot drive this. Each tick claims a few queued sets, processes them, and re-invokes itself while work remains. Progress lives in the database, so an interrupted chain loses nothing and the gallery's "Lanjutkan" button starts a new one.

**Interfaces:**
- Produces:
  ```ts
  export type ProcessDeps = { provider: AIProvider; putBlob: typeof putBlob; measure: TextMeasurer; loadImage: RenderOpts["loadImage"] };
  /** Clipart -> describe -> style -> expand -> a 600px mockup per member. Never throws for an expected failure. */
  export async function processSet(row: SetRow, deps: ProcessDeps): Promise<{ style: SetStyle; aiFallback: boolean; memberStates: MemberStates; status: "ready" | "failed"; error?: string }>;
  export const TICK_BATCH = 3;      // sets per tick, matching spec §8.2 concurrency
  ```
- The route: `POST /api/batch/[id]/tick`. It claims up to `TICK_BATCH` sets atomically (`UPDATE sets SET status='processing' WHERE id IN (SELECT id FROM sets WHERE batch_id=$1 AND status='queued' ORDER BY created_at LIMIT $2 FOR UPDATE SKIP LOCKED) RETURNING *`) so two overlapping ticks cannot process the same set. It processes them with `Promise.all`, writes each result, updates the batch's roll-up counts, and if any `queued` remain re-invokes itself through `waitUntil`; otherwise it sets the batch to `ready`. It returns `{ processed, remaining }` as JSON.
- Guard the route: it must only be callable for a batch that exists, and it does no work if the batch is already `ready` or `exported`.

### Task 8: Streaming batch ZIP export

**Files:**
- Create: `src/lib/batchZip.ts`
- Modify: `src/app/actions/batches.ts` (`exportBatchAction`), `src/app/api/batch/[id]/tick/route.ts` (an export mode) or a sibling `export/route.ts`
- Test: `tests/lib/batchZip.test.ts`

**Why streaming:** one set's render peaks near 380 MB and produces about 2.7 MB of output. Accumulating 200 sets before zipping is over a gigabyte of buffers and will exhaust a function. `fflate`'s `Zip` + `ZipPassThrough` emits chunks as each file is added, so only the current set is ever in memory.

**Interfaces:**
- Produces:
  ```ts
  export type BatchZipDeps = { measure: TextMeasurer; loadImage: RenderOpts["loadImage"]; clipartSize: (src: string) => Promise<ClipartSize> };
  /** Streams one folder per set plus report.csv, resolving to the stored ZIP's URL. */
  export async function streamBatchZip(opts: {
    batchId: string;
    sets: AsyncIterable<SetRow>;          // approved sets, streamed from the database
    deps: BatchZipDeps;
    put: (path: string, body: ReadableStream, contentType: string) => Promise<string>;
  }): Promise<{ url: string; files: number; failures: { set: string; member?: string; error: string }[] }>;
  ```
- ZIP layout (spec §8.2): `<sku_prefix or slug(kidName)>/<label>.png` per member, plus `report.csv` at the root listing every set and member with its status and any error. A folder name collision (two Keisyas, no sku) gets a `-2` suffix.
- A member that fails to render is recorded in `report.csv` and skipped; the export continues. A set that fails entirely is recorded and skipped.
- `putBlob` must accept a `ReadableStream` for this; verify `@vercel/blob`'s `put` supports it and adjust `src/lib/blob.ts` to add a `putBlobStream` rather than changing the existing signature.

## What this plan deliberately leaves out

- **Auth.** Spec §2 puts it out of scope; the deployment is protected by Vercel Authentication instead. If the shop ever opens it up, auth comes before anything else, because every action is unauthenticated.
- **woff2 subsetting.** The editor eagerly loads about 1.3 MB of TTF. Real, but a page-weight issue, not a batch one.
- **Real shirt photos and a licensed script font.** Both are the shop's to supply; the asset format and the font registry already accept them.
- **Template fidelity to the reference sample.** The output was looser than the sample when this plan was written; the human has since retuned the collage template against `docs/samples/single_ayah.png`.
