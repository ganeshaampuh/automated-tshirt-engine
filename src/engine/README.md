# Design engine

Pure TypeScript. No React, no DOM, no Next.js, no network. Everything that
draws pixels for this app goes through here so single mode, batch previews and
print export cannot drift.

Flow: `Set` (input + style) → `expand()` → one `Design` per member →
`renderDesign()` / `exportPrintPng()` / `renderMockup()`.

- Coordinates are print pixels at 300 DPI. Canvas is a square of
  `maxPx(sizeClass)` (adult 29 cm, kids 0–1 18 cm, kids 1–9 20 cm).
- Layers must stay inside the 3% safe area; `isWithinSafeArea()` guards export.
- Layer ids from the Collage template are stable: `numeral, clipart, top,
  ordinal, occasion, bottom`. Member `overrides` are keyed by these ids.
- Fonts: only families in `fonts.ts`, files in `public/fonts`. Every family
  ships as **static instances**, one file per weight — never a variable font,
  because skia (`@napi-rs/canvas`) ignores the `wght` axis and would print the
  default instance whatever weight the layer asks for, while Chrome applies it.
  `nearestWeight(family, weight)` maps a requested weight onto a shipped face
  (a single-weight family resolves 700 to its 400 file) and both renderers and
  both measurers go through it, so measure and draw always agree. Register the
  faces in any new Node renderer via `registerFonts()` from `fonts.node.ts`; in
  the browser load them by URL with `fontUrl(family, weight)`.
- Golden tests live in `tests/engine/__golden__`. Regenerate deliberately with
  `UPDATE_GOLDEN=1 pnpm test` and inspect the PNGs before committing. Mockup
  goldens (`mockup-*.png`) are regenerated by deleting them from
  `tests/engine/__golden__` and rerunning the mockup test.

## Two entry points

`@/engine` (`src/engine/index.ts`) is **isomorphic**: types, sizing, fonts
metadata, text, textFit, wording, templates and expand. It reaches no
`node:*` module, no `@napi-rs/canvas` and no `sharp`, so a client component may
import it. `tests/engine/isomorphic.test.ts` walks the barrel's relative import
graph and fails if anything node-only creeps back in.

`@/engine/server` (`src/engine/server.ts`) is the **server-only** entry point:
`createNodeMeasurer`, `ensureNodeFonts`, `renderDesign`, `loadImageFromFile`,
`exportPrintPng`, `ExportError`, `renderMockup`, `loadShirtAsset`,
`defaultShirtFor`, `ShirtAssetSchema`, `fontFilePath`, `registerFonts`. Import it
only from server code (route handlers, scripts, tests).

`loadImageFromFile` is deliberately unguarded: it loads whatever src it is handed. App code must
never pass it to a renderer directly — wrap it in `guardRemoteImages()` (`src/lib/sets.ts`), which
routes an `https:` src through `fetchRemoteImage` and refuses any other src that is not a
`data:image/` URI or a path this app ships. A member override can put an arbitrary string in a
layer's `src`, and in batch mode the clipart address comes out of a spreadsheet.

Browser rule: never touch font *files* or the filesystem from the browser — load
fonts by URL with `fontUrl(family, weight)` and measure text with the browser measurer,
which implements the same `TextMeasurer` interface (`textFit.ts`) that
`createNodeMeasurer` does.

## Known limitations

- `layerBounds()` is ink-aware: a text layer's box is `maxWidth` × `size · lines · (1 +
  DESCENDER_RATIO)`, grown by the stroke width on every side, so descenders and the outer half of a
  stroke are accounted for. It is still a conservative *envelope* rather than a per-glyph trace — a
  line with no descender (a numeral, say) reserves height it does not use — so `isWithinSafeArea()`
  and `boundingBoxCm()` never under-report, but may over-report. `exportPrintPng()` keeps its 1%
  margin.
